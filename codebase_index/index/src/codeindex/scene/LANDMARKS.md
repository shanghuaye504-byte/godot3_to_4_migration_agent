## 先分清三个函数

- `check_scene(text, path, *, repo_classes, rules_db_path, file_exists)`：对一份场景正文做静态检查。
- `scene_check(conn, project_root, *, paths=None, rules_db_path=None)`：汇总索引范围、基线差异和覆盖，返回字典。
- `diff_baseline(conn, current)`：当前返回 `DiffResult`，新增 checked_scenes 时保留这个返回类型；问题路径是 `Problem.path`，没有 location.path。

冻结 API 是 S05 新增，不可把数据库连接当正文交给 `check_scene`。`scene_refs` 没有 to_node_path 列；回调归属必须连到真实的 connection 目标和挂载脚本。

## 增量与最终验收的区别

局部检查只承诺所检查范围；最终成功门必须全量检查。`pre_existing` 代表 L0 后已存在的问题，仍要解决或作为残留报告，不能因在基线里就当作通过。继承/实例子树弃权、二进制/超大文件跳过必须保留覆盖说明。

测试先用静态夹具验证解析/归属；`scenecheckfixture` 的孤立资源不具备完整项目依赖，不用 ResourceLoader.load 验收它们。动态资源测试另用 S01 的完整小项目。
